# Completion Policy

## Completion Standard

Target 100% completion of defined and authorized acceptance criteria.

Completion requires **verified operational functionality**, not:
- Documentation created
- Plan generated
- Task assigned
- Configuration written
- Untested workflow created
- Deployment attempted

## Completion States

| State | Description |
|-------|-------------|
| NOT STARTED | No work begun |
| DISCOVERED | Requirements identified |
| IMPLEMENTING | Work in progress |
| IMPLEMENTED | Code/configuration written |
| LOCALLY TESTED | Passed local tests |
| CONNECTED | Integration validated |
| LIVE VALIDATED | Live endpoint tested |
| DEPLOYED | Running in target environment |
| OPERATIONAL | Confirmed working |
| MONITORED | Active monitoring in place |
| BLOCKED | Cannot proceed (evidence required) |
| FAILED | Attempted but failed (evidence required) |

## Evidence Requirements

For each completed requirement, provide:
- What was done
- How it was verified
- Test output or validation result
- Timestamp of verification

## Reporting

Final report must include:
- Actions actually executed
- Resources created or modified
- Configurations implemented
- Integrations connected
- Problems resolved
- Tests executed and results
- Deployment status
- Active automation status
- Remaining blockers (with evidence)
- Verified completion percentage

## Prohibited Completion Claims

- Do not claim completion based on documentation alone
- Do not claim completion based on local tests alone
- Do not claim completion based on attempted deployments
- Do not fabricate successful execution
- Do not conceal unresolved problems
