09 / PROPOSED DELIVERY ORDER

Implementation sequence reduces risk.

Build the persistent model and enforcement points first, then add editing capability, and only then permit a controlled approval and export flow.

EACH STAGE HAS A VERIFICATION GATE
01
NORMALIZE THE DATA MODEL
Align documentary status enums, relationship approvals, and add document version fields.
02
DEFINE API CONTRACTS
Shared DTOs, stable error envelope, authorization service, and transition validation.
03
LOAD THE AGGREGATE
Workspace read endpoint, case-scoped resource search, and role-aware visibility tests.
04
PERSIST STRUCTURE
Chapter/item CRUD, batch reorder, relationship review, and transactional audit writes.
05
CONNECT THE UI
Replace static cards with data-backed components and conflict-aware mutation states.
06
APPROVE + EXPORT
Readiness checks, reproducible snapshots, and end-to-end Owner/Admin/Guest flow testing.
EVIDENCE OF
COMPLETION
SCHEMA + API

Migration review, enum compatibility, authorization, validation, and error-contract unit tests.

WORKSPACE + MUTATIONS

Aggregate-read, transaction, reorder, conflict, relationship, and audit assertions.

FINAL REVIEW FLOW

Create → edit → submit → reject/modify → approve → export snapshot → audit verification.
